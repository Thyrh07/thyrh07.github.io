## **<span style='color:#ff5555'>Ringkasan</span>**
***

Ruby2Shell adalah kerentanan heap overflow di Ruby yang memungkinkan remote code execution (RCE) — dalam konfigurasi default Rails dan Sinatra, tanpa autentikasi — lewat satu karakter: huruf Jerman ß (sharp s). Kerentanan ini diungkap 19 November 2026 oleh Veria Labs, sehari setelah tim Ruby merilis patch.

- **CVE:** CVE-2026-132825 (GHSA-34m4-m9fh-gqp5)
- **Nama:** Ruby2Shell (juga ditulis "ruby2ßhell")
- **Jenis:** One-byte heap-based buffer overflow (CWE-122 / CWE-193) di konversi case string Ruby
- **Skor:** CVSS 3.1 7.4 (High, dari MITRE) per Censys advisory; tim Ruby menilainya Critical
- **Penemu:** Veria Labs — menemukan celah ini secara independen dan pertama kali mendemonstrasikan RCE; analisis jalur lewat Rack oleh Moritz Sanft, dipublikasikan di hari yang sama
- **Pemicu utama:** Request HTTP biasa ke aplikasi Rails default atau Sinatra classic-style — tidak perlu login, kode aplikasi sendiri bahkan belum sempat jalan
- **Terdampak:** Ruby 3.3.13 ke bawah, 3.4.0–3.4.12, dan 4.0.0–4.0.9; bug-nya sudah ada sejak Ruby 2.4.0
- **Status eksploitasi:** Belum ada eksploitasi di alam liar yang dilaporkan per 21 November 2026; tim Ruby menyatakan sudah tahu ada PoC non-publik yang mencapai RCE di beberapa skenario. Veria Labs berencana merilis PoC RCE untuk Rails pada **25 November 2026** — atau lebih lambat kalau vendor besar belum merilis fix

> ⚠ **Klarifikasi penting:** Ruby2Shell bukan malware dan bukan satu exploit universal. Yang bocor adalah satu byte heap — mengubahnya menjadi RCE butuh rangkaian exploit lanjutan, dan PoC publik belum ada sampai 25 November. Tapi jangan jadikan itu alasan menunda patch: celahnya terjangkau sebelum autentikasi di framework default, dan fix-nya sudah tersedia sejak 18 November.

## **<span style='color:#ff5555'>Apa Itu Ruby2Shell</span>**
***

Akar masalahnya sederhana dan sudah lama ada: huruf Jerman ß tidak punya huruf kapital satu karakter di sebagian besar encoding single-byte. Huruf kapitalnya adalah dua karakter, `SS`. Saat Ruby mengubah case string dalam encoding seperti ISO-8859-1 atau Windows-1252, ia menulis dua byte `SS` — tapi loop-nya hanya memeriksa ruang untuk satu byte (`to < to_end`).

Buffer output dialokasikan sebesar panjang input ditambah 20 byte. Setiap ß menambah satu byte ke output, jadi string dengan 21 karakter ß meluberkan buffer tepat satu byte. Byte yang tertulis itu adalah `S` (0x53) saat upcase, atau `s` (0x73) saat case-folding, dan mendarat tepat setelah buffer output. Menyalin hasil keluar dari buffer kemudian membaca satu byte di luar batas.

Yang membuat celah ini berbahaya bukan bug-nya yang besar — cuma satu byte — melainkan jalurnya yang terbuka lebar:

1. Penyerang mengirim form request biasa ke aplikasi Rails, dengan parameter `_method` berisi string ß berulang dalam encoding single-byte
2. Rack — lapisan di bawah Rails — memproses request itu lewat middleware MethodOverride, yang mengubah nilai `_method` ke huruf kapital **sebelum kode aplikasi atau autentikasi apa pun jalan**
3. Pemanggilan `upcase` itu mengenai bug case conversion, dan heap tercorrupt
4. Dari primitive satu byte itu, exploit yang dirangkai dengan hati-hati bisa mencapai RCE — Veria Labs sudah mendemonstrasikannya, dan tim Ruby mengonfirmasi ada PoC yang mencapai RCE di beberapa skenario

Metode yang mencapai bug ini: `upcase`, `swapcase`, `downcase(:fold)`, dan `casecmp?`. String UTF-8 **tidak** terdampak — hanya encoding single-byte: 14 varian ISO-8859 dan Windows-125x, termasuk ISO-8859-1, ISO-8859-2, Windows-1250, Windows-1252, Windows-1254, dan Windows-1257.

## **<span style='color:#ff5555'>Tujuh Celah dalam Satu Rilis</span>**
***

Ruby2Shell bukan satu-satunya yang diperbaiki rilis 18 November. Rilis yang sama menutup **tujuh** kerentanan memory safety di regex engine dan kode konversi case string Ruby: tiga Critical, tiga High, dan satu Moderate. Tiga yang Critical punya PoC RCE dari peneliti.

Enam dari tujuh celah itu belum punya nomor CVE per 21 November 2026 — tim Ruby sudah memintanya, dan sampai ditugaskan, ID advisory GitHub (GHSA) adalah satu-satunya cara melacaknya di scanner dan inventaris software. Salah satu yang terkait, GHSA-87fm-7w84-j2px, adalah integer overflow di konversi case string yang sama — Cloudflare menambahkan rule WAF untuknya bersama rule Ruby2Shell.

## **<span style='color:#ff5555'>Deteksi dan Mitigasi</span>**
***

### 1. Patch Segera — Remediasi Utama

- Update Ruby ke **3.3.14, 3.4.13, atau 4.0.10** — sesuai branch yang dipakai. Satu upgrade ini menutup ketujuh celah sekaligus
- Restart semua proses aplikasi setelah upgrade interpreter — proses yang sudah berjalan tetap memakai binary Ruby lama sampai di-restart. Di container, rebuild dari base image yang sudah diperbarui dan buat ulang container
- Untuk software self-hosted (GitLab, Mastodon, Chatwoot, dan lainnya): ikuti rilis vendor di tabel atas, bukan hanya upgrade Ruby host
- Verifikasi setelah restart: `ruby -v` harus menunjukkan 3.3.14, 3.4.13, atau 4.0.10

### 2. Mitigasi Sementara Bila Patch Tertunda

- **Tidak ada workaround resmi yang dipublikasikan.** Tim Ruby tidak merilis workaround — upgrade adalah satu-satunya remediasi
- Cloudflare WAF sudah menambahkan dua rule (Block sebagai aksi default, termasuk untuk pelanggan Free plan): satu untuk Ruby2Shell dan satu untuk GHSA-87fm-7w84-j2px. Itu compensating control, bukan pengganti patch — Cloudflare sendiri menegaskan exploit bisa mencapai bug lewat jalur yang tidak dilihat WAF
- Kalau aplikasi menerima input dalam encoding single-byte legacy (ISO-8859 / Windows-125x), normalisasi input ke UTF-8 sedini mungkin di edge — tapi ini bukan perbaikan, hanya mengurangi permukaan serangan

### 3. Cara Cek Cepat

```bash
# Versi Ruby yang benar-benar berjalan
ruby -v

# Cari aplikasi Ruby/Rails yang berjalan di server ini
ps aux | grep -E '[r]uby|[p]uma|[u]nicorn|[s]idekiq' | head

# Cek versi Ruby yang dipakai tiap aplikasi (lewat Gemfile / .ruby-version)
find /var/www /opt /srv -maxdepth 4 -name '.ruby-version' 2>/dev/null -exec sh -c 'echo "== $1"; cat "$1"' _ {} \;
```

`ruby -v` yang menunjukkan 3.3.13 ke bawah, 3.4.12 ke bawah, atau 4.0.9 ke bawah berarti rentan — kecuali aplikasi itu tidak pernah memanggil konversi case pada input dengan encoding single-byte, yang praktis tidak bisa dijamin untuk Rails default.

Jangan menjalankan PoC atau test exploit publik terhadap server produksi sebagai metode inventarisasi — apalagi PoC resminya baru dijadwalkan rilis 25 November.

## **<span style='color:#ff5555'>Kesimpulan</span>**
***

Ruby2Shell berbahaya bukan karena bug-nya besar — cuma satu byte — melainkan karena jalurnya: request biasa ke Rails default mencapai bug itu sebelum autentikasi, lewat middleware yang memang selalu jalan. Bug-nya sudah ada sejak Ruby 2.4.0, sepuluh tahun, dan menunggu satu huruf ß dalam encoding yang tepat.

Tiga hal yang perlu diingat: patch adalah remediasi utama dan butuh restart proses, bukan sekadar update gem; Rails atau `bundle update` saja tidak memperbaiki apa-apa karena fix-nya di interpreter; dan software self-hosted seperti GitHub Enterprise Server butuh rilis vendor sendiri — upgrade Ruby host tidak membantu.

Periksa `ruby -v` di semua tempat aplikasi Ruby berjalan, update ke 3.3.14, 3.4.13, atau 4.0.10, dan lakukan sebelum PoC publik keluar 25 November.
