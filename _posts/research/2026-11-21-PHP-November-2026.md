## **<span style='color:#ff5555'>Ringkasan</span>**
***

Rilis keamanan PHP 19 November 2026 memperbaiki 17 kerentanan di semua branch yang masih didukung — tujuh di antaranya Critical dengan skor CVSS 4.0 **9.2**, dan sebagian besar membuka jalan ke remote code execution (RCE) sebagai PHP worker. Ini rilis kritis PHP kedua dalam empat minggu: patch PHP2Shell 21 Oktober tidak menutup satu pun celah di daftar ini.

- **CVE utama:** CVE-2026-126714 (phpAfterShell) dan CVE-2026-129289 (PHP-FPM request smuggling), plus CVE-2026-115560, CVE-2026-129481, CVE-2026-129474, CVE-2026-129182, dan CVE-2026-129496
- **Nama:** phpAfterShell (untuk CVE-2026-126714); rilis ini sendiri tidak punya satu nama payung
- **Jenis:** Deserialisasi objek lewat session handler, request smuggling di PHP-FPM, dan beberapa use-after-free di core/session/date
- **Skor:** CVSS 4.0 **9.2 (Critical)** untuk ketujuh CVE kritis menurut PHP Group
- **Penemu:** depthfirst melaporkan phpAfterShell (CVE-2026-126714); CVE-2026-115560 sudah diumumkan PHP sebagai advisory informasional sejak 23 Oktober 2026
- **Pemicu utama:** Tergantung celah — upload file biasa (phpAfterShell), request HTTP biasa ke aplikasi yang membuka `php://input` tanpa membacanya sampai habis (PHP-FPM request smuggling), atau session upload progress yang menyala (CVE-2026-115560). Sebagian jalur tidak butuh login
- **Terdampak:** PHP 8.2.0–8.2.35, 8.3.0–8.3.36, 8.4.0–8.4.27, dan 8.5.0–8.5.12 (tidak semua CVE kena semua branch — lihat tabel di bawah). PHP 8.1 ke bawah sudah EOL dan tidak menerima fix
- **Status eksploitasi:** Belum ada laporan eksploitasi di alam liar per 21 November 2026 (Wiz, ASEC/AhnLab)

> ⚠ **Klarifikasi penting:** Ini bukan satu exploit universal, dan bukan berarti semua server PHP langsung bisa di-RCE dari internet. Ketujuh celah kritis itu masing-masing punya syarat: konfigurasi front-end tertentu, session handler tertentu, atau gadget chain di kode aplikasi. Tapi jangan jadikan itu alasan menunda patch — syarat-syarat itu umum di deployment nyata (FastCGI connection reuse, file session handler bawaan PHP, upload progress yang dulu default menyala), dan patch-nya sudah tersedia sejak 19 November. Yang sudah patch PHP2Shell bulan lalu tetap rentan sampai memasang rilis ini.

## **<span style='color:#ff5555'>Apa Itu phpAfterShell dan Rilis November 2026</span>**
***

phpAfterShell adalah nama yang diberikan depthfirst untuk CVE-2026-126714 — dan namanya sengaja dipilih karena celah ini lolos dari fix PHP2Shell.

Empat minggu sebelumnya, 21 Oktober 2026, PHP merilis patch darurat untuk PHP2Shell (CVE-2026-109618 dan CVE-2026-109619, keduanya 9.2) — use-after-free yang bisa dijangkau lewat session upload progress sebelum kode aplikasi jalan. depthfirst kembali mengaudit kode yang sudah di-patch itu dan bertanya: exploit Oktober memang sudah tidak bekerja, tapi apakah operasi yang mendasarinya sudah benar-benar aman? Ternyata belum.

Session handler file bawaan PHP (`session.save_handler = files`, default PHP) menulis data session ke disk dengan `pwrite()` lalu `ftruncate()` — dua system call terpisah, tanpa jaminan atomik di antaranya. Kalau worker PHP mati di tengah penulisan — karena limit memori atau timeout — file session yang tersisa adalah campuran byte lama dan byte baru. Saat request berikutnya memanggil `session_start()`, PHP menjalankan deserializer atas campuran itu, dan penyerang yang mengendalikan sebagian isi session bisa membentuk aliran data itu menjadi object injection. Dirangkai dengan gadget chain di kode aplikasi, primitive itu menjadi RCE sebagai PHP worker.

Pemicu paling mudahnya adalah session upload progress: fitur yang mencatat progres upload file ke dalam session pengguna, menyala secara default sejak PHP 5.4.0 (2012). Upload multipart biasa yang menyertakan field `PHP_SESSION_UPLOAD_PROGRESS` sebelum data file membuat PHP menulis state progres ke file session sebelum satu baris pun kode aplikasi berjalan. Rilis 19 November juga mengubah default fitur ini menjadi mati.

Enam CVE kritis lainnya bukan varian phpAfterShell — masing-masing jalur independen:

1. **CVE-2026-129289 — PHP-FPM request smuggling.** PHP tidak membuang sisa body request HTTP yang belum dibaca saat request shutdown, kalau aplikasi membuka `php://input` tanpa membacanya sampai habis. Kalau front-end memakai ulang koneksi FastCGI ke PHP-FPM, sisa byte itu diparse sebagai request FastCGI baru — request yang tidak pernah dibuat atau diotorisasi web server. Penyerang menyisipkan request palsu di akhir body, lengkap dengan parameter FastCGI pilihannya sendiri (`SCRIPT_FILENAME`, `REMOTE_ADDR`, `PHP_ADMIN_VALUE`), dan mengeksekusi kode PHP pilihannya sebagai worker — tanpa login, dalam satu request. Bug ini sudah ada sejak PHP 5.6.0. Syaratnya: front-end yang memakai ulang koneksi backend, misalnya nginx dengan `fastcgi_keep_conn on`, Apache `mod_proxy_fcgi` dengan `enablereuse=on`, HAProxy FastCGI, atau LSAPI.
2. **CVE-2026-115560 — session serializer mismatch.** Session upload progress menyala, dan data session ditulis dengan satu serializer lalu dibaca dengan serializer lain — misalnya `php_binary`/`php_serialize` di INI, atau aplikasi yang beralih ke `php` sebelum `session_start()`. Bisa juga terjadi tanpa perubahan runtime, kalau beberapa aplikasi, pool, atau job CLI dengan setting berbeda berbagi satu session store. Hasilnya deserialisasi objek yang dikendalikan penyerang; RCE butuh gadget chain di aplikasi.
3. **CVE-2026-129481 — use-after-free di session shutdown** (8.3–8.5). Shutdown session yang terinterupsi bisa crash worker yang dipakai ulang, atau berpotensi RCE, tergantung perilaku aplikasi.
4. **CVE-2026-129474 — use-after-free di backtrace magic method** (hanya 8.5). Data request yang membentuk alokasi, magic method yang terjangkau, dan fatal error di momen yang tepat bisa berujung RCE.
5. **CVE-2026-129182 — use-after-free lewat repopulasi `last_fatal_error_backtrace` setelah shutdown** (hanya 8.5). Satu kelas bug yang sama dengan CVE-2026-109619 dari PHP2Shell.
6. **CVE-2026-129496 — use-after-free di timezone cache** (8.2–8.5). Terpicu misalnya saat PHP menulis warning atau deprecation ke error log berbasis file saat startup, dari setting `date.timezone` yang tidak valid. Penyerang tanpa login bisa crash worker atau menjalankan kode sebagai worker.

Sepuluh CVE sisanya berkategori high/medium dan menyentuh PHP-FPM, CGI, Phar, SOAP, DOM, stream HTTP/FTP, dan URI handling.

PHP merilis 8.2.36 / 8.3.37 / 8.4.28 / 8.5.13 pada 19 November 2026 (sekitar 14:02 UTC). Tidak perlu pindah ke 8.6 untuk mendapat fix — update branch yang sama sudah cukup.

Perhatian: **8.2.36 adalah salah satu rilis keamanan terakhir branch 8.2** — dukungan keamanan 8.2 berakhir 31 Desember 2026. Kalau masih di 8.2, rencanakan migrasi sekarang, bukan setelah EOL. Paket distro sering mem-backport fix tanpa mengubah string versi — AlmaLinux misalnya merilis paket ter-patch di hari yang sama — jadi bandingkan versi paket lengkap dengan advisory distro, bukan hanya output `php -v`. Dan `php -v` di host hanya bicara soal binary CLI, bukan worker yang melayani request — cek versi di dalam container yang sedang berjalan atau SBOM image-nya.

## **<span style='color:#ff5555'>Deteksi dan Mitigasi</span>**
***

### 1. Patch Segera — Remediasi Utama

- Update ke **8.2.36 / 8.3.37 / 8.4.28 / 8.5.13** sesuai branch, atau **8.6.0**
- **Restart semua PHP worker setelah update** — FPM master, Apache dengan mod_php, runtime embedded. Kode lama tetap di memori sampai prosesnya diganti
- Di container, rebuild dari image yang sudah diperbarui dan buat ulang container — pull image baru tidak mengganti proses yang sudah berjalan
- Verifikasi setelah restart: cek versi PHP yang benar-benar melayani request, bukan hanya CLI di host

### 2. Mitigasi Sementara Bila Patch Tertunda

Langkah-langkah ini tidak memperbaiki kode — masing-masing hanya menutup celah yang disebutkan:

- Untuk phpAfterShell dan CVE-2026-115560: set `session.upload_progress.enabled = 0` di `php.ini`, pool FPM, atau konfigurasi PHP web server — bukan lewat `ini_set()` di runtime, karena itu sudah terlambat. Lalu restart worker. Ini mitigasi parsial: menutup jalur upload, tapi aplikasi yang menyimpan data yang dikendalikan penyerang ke session lewat cara lain tetap terdampak
- Untuk CVE-2026-129289: matikan pemakaian ulang koneksi backend — nginx `fastcgi_keep_conn off`, Apache `enablereuse=off` pada worker `mod_proxy_fcgi` — supaya koneksi ditutup setelah tiap request
- Pastikan listener PHP-FPM dan LSAPI tidak terekspos langsung ke jaringan yang tidak tepercaya

### 3. Cara Cek Cepat

```bash
# Versi binary yang benar-benar berjalan (di dalam container yang sedang berjalan)
php -v
php-fpm -v

# Apakah upload progress menyala (harus 0 setelah patch, kecuali sengaja dihidupkan lagi)
php -i | grep -i 'session.upload_progress.enabled'

# Apakah nginx memakai ulang koneksi FastCGI (salah satu syarat CVE-2026-129289)
grep -rn 'fastcgi_keep_conn' /etc/nginx/ 2>/dev/null

# Apakah ada kode yang membuka php://input (jalur lain syarat CVE-2026-129289)
grep -rn 'php://input' --include='*.php' /path/to/app | head -20

# Session handler apa yang dipakai (files = default, in scope CVE-2026-126714)
php -i | grep -i 'session.save_handler'
```

Jangan menjalankan PoC atau test exploit publik terhadap server produksi sebagai metode inventarisasi.

## **<span style='color:#ff5555'>Kesimpulan</span>**
***

Rilis November 2026 berbahaya bukan karena sudah dieksploitasi di mana-mana — sampai 21 November belum ada laporan eksploitasi di alam liar — melainkan karena pola yang ia tunjukkan: celah kedua yang ditemukan justru saat mengaudit ulang fix celah pertama. Patch PHP2Shell Oktober menutup exploit-nya, tapi tidak menyentuh cara file session ditulis — dan di situlah phpAfterShell masuk.

Tiga hal yang perlu diingat: update ke branch yang sama sudah cukup, tidak perlu lompat ke 8.6; restart worker setelah update, karena binary baru tidak mengganti proses yang sedang berjalan; dan 8.2 hampir habis masa dukungannya — 31 Desember 2026 — jadi rencanakan migrasi dari sekarang.

Periksa versi PHP yang benar-benar melayani request, update ke 8.2.36 / 8.3.37 / 8.4.28 / 8.5.13, dan restart semua worker.
